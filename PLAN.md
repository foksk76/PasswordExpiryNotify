# Implementation Plan: PasswordExpiryNotifyChange.ps1

## Overview

Создать второй скрипт `PasswordExpiryNotifyChange.ps1` на основе
`PasswordExpiryNotify.ps1` (который не меняется): предупреждение об истечении
пароля + кнопка «Сменить пароль», открывающая диалог с вставкой старого и нового
пароля из буфера и сменой через ADSI `ChangePassword` без прав администратора.

## Architecture Decisions

- **Два независимых скрипта.** Логика предупреждения копируется в новый файл
  (дублирование сознательное — выбор скрипта при развёртывании зависит от
  политики ИБ). `PasswordExpiryNotify.ps1` не трогаем.
- **WPF-окно вместо MessageBox** для кнопок «Сменить пароль»/«Позже».
  PresentationFramework уже подключён в оригинале.
- **Смена через `IADsUser.ChangePassword`** через уже связанный
  `LDAP://<SID=...>`; при ошибке фолбэк на `WinNT://ДОМЕН/пользователь`
  (классический вариант из SANS ISC 28036).
- **Кнопка «Вставить из буфера» у каждого поля** читает `Get-Clipboard -Raw` —
  гарантированная вставка независимо от поведения `Ctrl+V` в WPF PasswordBox.
- **Очистка буфера** после успешной смены (`Set-Clipboard $null`), не при отмене.
- Пароли — только в памяти (`PasswordBox.Password` и локальные переменные),
  не логируются, не пишутся на диск.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| WPF `Ctrl+V` в PasswordBox не сработает в какой-то сборке .NET | Med | Явная кнопка «Вставить из буфера» (`Get-Clipboard -Raw`) как гарантированный путь |
| `ChangePassword` по LDAP упадёт (подпись/шифрование) в части окружений | Med | Фолбэк на `WinNT://ДОМЕН/пользователь` (проверенный SANS-путь) |
| Неверный старый пароль / нарушение политики | Low | Ошибка `ChangePassword` ловится, показывается, диалог не закрывается |
| Синтаксис PowerShell без локальной Windows-машины | Med | Статическое ревью + парсер PowerShell на Windows перед развёртыванием |
| Расхождение логики двух скриптов со временем | Low | Ревью при правках; комментарий-перекрёстная ссылка в шапках файлов |
