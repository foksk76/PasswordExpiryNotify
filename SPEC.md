# Spec: Дополнительный скрипт — предупреждение + смена пароля с вставкой из буфера

## Objective

Сейчас после предупреждения об истечении пароля пользователь меняет его только
через `Ctrl+Alt+Del/End` → «Сменить пароль» — этот диалог работает на secure
desktop, где вставка из буфера недоступна. Сложные пароли (большая длина,
спецсимволы), которые пользователь хранит в KeePass/Passbolt, приходится
вводить вручную — медленно и с ошибками.

Создаётся **новый скрипт** на основе `PasswordExpiryNotify.ps1`, который
добавляет **альтернативный способ смены пароля**: в окне предупреждения
появляется кнопка «Сменить пароль», открывающая диалог с полями
«текущий / новый / подтверждение». Пользователь вставляет пароли из буфера
обмена (обычный рабочий стол, где вставка работает), а скрипт меняет пароль
через ADSI `ChangePassword`. Secure desktop не задействуется.

**Два скрипта в репозитории — два сценария применения**, выбор делается при
развёртывании в зависимости от требований ИБ:

- `PasswordExpiryNotify.ps1` — только предупреждение (как сейчас, **не
  меняется**). Вариант для организаций, где смена пароля из клиентского
  скрипта запрещена политикой ИБ.
- `PasswordExpiryNotifyChange.ps1` — предупреждение + кнопка смены пароля с
  вставкой из буфера. Вариант, где такой способ разрешён.

## Решения и допущения

1. **Нужен старый пароль** — `ChangePassword($old, $new)` работает у обычного
   пользователя без прав администратора (в отличие от `SetPassword`,
   `Set-ADAccountPassword`, `net user`). Старый пароль пользователь тоже
   вставляет из менеджера паролей.
2. **MessageBox заменяется на собственное WPF-окно** — у стандартного
   MessageBox нельзя задать кастомные кнопки. PresentationFramework уже
   подключается в скрипте.
3. **Тексты диалога на русском** — в духе текущих значений `-Message`/`-Title`.
   Параметр `-Message` (с `{0}`) по-прежнему управляет текстом предупреждения.
4. **Вставка из буфера**: стандартный `Ctrl+V` в WPF PasswordBox + явная кнопка
   «Вставить из буфера» у каждого поля (читает `Get-Clipboard -Raw`). Блокируем
   ввод пустых значений и несовпадение «новый ≠ подтверждение».
5. **Очистка буфера** после успешной смены пароля (пароль был в буфере),
   но не при отмене.
6. **Новый пароль в KeePass/Passbolt пользователь обновляет сам** — скрипт не
   имеет доступа к базам менеджеров паролей. Успешное сообщение это напоминает.
7. **Запуск в интерактивной сессии пользователя** (запланированное задание в
   Конфигурации пользователя) — GUI-окно показывается и по RDP, где `Ctrl+V`
   в обычные окна работает.
8. **Только PowerShell 5.1 + WPF + ADSI**, без новых модулей и зависимостей.
9. **`PasswordExpiryNotify.ps1` не изменяется** — логика предупреждения
   копируется в новый файл. Дублирование сознательное: два независимых
   скрипта для разных политик ИБ; расхождения при правках контролируются
   ревью (см. «Границы»).
10. Ранние выходы (не в домене, пароль не истекает, `DONT_EXPIRE_PASSWD`,
    `msDS-...` без значения) и тихие ошибки через `Write-Warning` — как в
    оригинале.

## Code Style

Скрипт однофайловый, функции в верхней части, `param()` первым,
`Set-StrictMode -Version Latest` после него. Строки и имена — как в текущем коде:

Конвенции:
- Функции с глаголом в имени: `Show-*`, `Change-*`
- WPF-окно собирается в коде через `New-Object` (без XAML-разметки)
- Пароли в памяти держать только в `PasswordBox.Password` / локальных
  переменных, в лог не писать, на диск не сохранять

## Testing Strategy

Тестового фреймворка в проекте нет (см. AGENTS.md). Проверка:

1. Синтаксис — парсером PowerShell (команда выше).
2. Ручной сценарий на Windows-машине в домене: предупреждение → «Сменить
   пароль» → вставка старых/новых паролей → успех; повторно — проверка, что
   старый пароль больше не подходит.
3. Негативные сценарии: пустые поля, «новый ≠ подтверждение», неверный
   текущий пароль, пароль не проходит политику домена — окно ошибки, диалог
   остаётся открытым.

## Границы

- **Всегда:** валидировать ввод в диалоге; очищать буфер после успеха; не
  логировать и не сохранять пароли; ловить и показывать ошибки `ChangePassword`.
- **Спросить сначала:** изменение UX предупреждения (замена MessageBox на
  кастомное окно в новом скрипте), добавление параметров скрипта, переименование
  `PasswordExpiryNotifyChange.ps1`.
- **Никогда:** не менять `PasswordExpiryNotify.ps1` (он остаётся вариантом
  «только предупреждение» для жёстких политик ИБ); не использовать
  `SetPassword`/`Set-ADAccountPassword`/`net user` (требуют прав), не отправлять
  пароли в secure desktop, не сохранять пароли в файлы/журнал/конфиги.

## Success Criteria

- [ ] Новый файл `PasswordExpiryNotifyChange.ps1` — копия `PasswordExpiryNotify.ps1`
      с добавленным диалогом смены пароля
- [ ] `PasswordExpiryNotify.ps1` не изменён (git diff пуст для него)
- [ ] Окно предупреждения имеет кнопки «Сменить пароль» и «Позже»
- [ ] Диалог смены содержит три поля + «Вставить из буфера» у каждого
- [ ] `Ctrl+V` в поле вставляет содержимое буфера
- [ ] Смена выполняется через ADSI `ChangePassword` без прав администратора
- [ ] Успех → окно «Пароль изменён…», буфер очищен
- [ ] Ошибки (пусто, несовпадение, неверный старый, политика) показаны,
      диалог не закрывается с потерей ввода
- [ ] Ранние выходы и тихие ошибки — как в оригинале
- [ ] README и AGENTS.md обновлены (два скрипта, сценарии по требованиям ИБ);
      код подписан вручную перед развёртыванием (см. README, подпись скрипта
      «ломается» от любой правки)
